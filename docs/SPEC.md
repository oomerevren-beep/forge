# Forge Package Spec — forge.toml

## 1. Full Example

```toml
[package]
name = "anthropics/plan"
version = "1.2.0"
type = "skill"
description = "Plan mode skill for Claude Code — structured planning before coding"
license = "MIT"
homepage = "https://github.com/anthropics/skills"
repository = "https://github.com/anthropics/skills"
author = "Anthropic <skills@anthropic.com>"
keywords = ["planning", "workflow", "claude-code"]
# Source: subpath when the upstream is a monorepo
source = "skills/plan"

[engines]
claude-code = ">=1.0.0"
opencode = ">=0.5.0"
codex = "*"
cursor = "*"
dsh = "*"

# Dependencies (forge packages)
[dependencies]
"obra/superpowers" = "^2.0.0"
"mcp/filesystem" = "^1.0.0"

# Which files ship in the package
[files]
include = ["SKILL.md", "scripts/**", "references/**", "assets/**"]
exclude = ["test/**", "*.log"]

# MCP config template (for mcp type)
[mcp]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
env = { "DEBUG" = "1" }

# Hooks (for plugin type)
[plugin]
entry = "index.js"
hooks = ["pre-tool", "post-tool"]

# Metadata (for skill type)
[skill]
name = "plan"
invocation = "/plan"
allowed-tools = ["Read", "Write", "Bash"]

[publish]
registry = "https://registry.forge.sh"
access = "public" # public | private
```

## 2. Fields

### [package]

- `name` (required): `scope/name` format, scope = GitHub org/user. E.g. `anthropics/plan`, `mcp/filesystem`
- `version` (required): semver `MAJOR.MINOR.PATCH`
- `type` (required): `skill` | `mcp` | `plugin` | `agent` | `command` | `hook`
- `description` (required): one-sentence description (for registry search)
- `license`, `homepage`, `repository`, `author`, `keywords` (optional but recommended)
- `source` (optional): subfolder inside a monorepo (e.g. `skills/plan`)

### [engines]

Which harnesses it runs on. `*` = all, `>=x` = version constraint. Empty means `*`.

### [dependencies]

Dependencies on other forge packages. Semver ranges: `^1.2.0`, `~1.2.0`, `*`, `>=1.0.0`.

### [files]

`include` globs ship in the package. `exclude` opts out. Default: `["**/*"]` minus `.git`, `node_modules`.

### Type-specific sections

- `[mcp]`: `command`, `args`, `env`
- `[plugin]`: `entry`, `hooks`
- `[skill]`: `name`, `invocation`, `allowed-tools`
- `[agent]`: `model`, `tools`, `prompt`

## 3. File Location

- Package roots must contain `forge.toml`
- Consumer (project) side may also have `forge.toml`:

```toml
# my-project/forge.toml — universal agent context (Docker for Context)
[project]
name = "my-fintech-app"
version = "1.0.0"

[dependencies]
"anthropics/plan" = "^1.2.0"
"mcp/filesystem" = "^2.0.0"
"obra/superpowers" = "^3.0.0"
```

`forge install` reads this file and installs everything (like `package.json` in npm).

### Universal project manifest (Phase 3)

One file declares the whole team context — roles, skills (any source),
MCP servers, and permission boundaries:

```toml
[project]
name = "my-fintech-app"
version = "1.0.0"

[agents.developer]
model = "claude-3-7-sonnet"
system_prompt = "You are a senior fintech engineer. TDD."

[skills]
"agent-pr-reviewer" = "^1.2.0"
"team-security-rules" = { source = "github:my-org/agent-security", ref = "main" }
"local-helper" = { source = "./packages/helper" }

[mcp.servers.postgres]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/db"]
env = { DB_SSL = "require" }

[permissions]
allowed_paths = ["./src", "./tests"]
denied_paths = [".env*", "id_rsa*", "./secrets"]
allow_network = false
```

`forge sync` distributes all of it to every detected editor in one run
(skills + rule files + MCP configs + agent-roles block + `forge.lock`).
`forge audit` enforces `[permissions].denied_paths` on package content.

## 4. Lockfile — forge.lock (Phase 2)

`forge install` writes a deterministic `forge.lock` pinning the exact
resolution: source URL + resolved version + SHA-256 integrity per package:

```toml
# Generated by Forge — do not edit manually

[[packages]]
name = "anthropics/plan"
version = "1.2.0"
type = "skill"
tarball = "https://github.com/.../plan-1.2.0.tar.gz"
sha256 = "abc123..."
source = "registry"
```

Rules:

- Entries are sorted by name; field order and LF endings are fixed — the
  same input always produces byte-identical output.
- `forge install --frozen` installs exactly the locked versions, then runs
  the integrity barrier: yanked versions (missing from the registry) and
  sha256 drift refuse the install with exit 1.
- Locks without integrity fields (pre-Phase-2) still parse; frozen installs
  treat placeholder hashes as unverified unless `--mock` is passed.

## 5. Validation

Before `forge publish`:

- `name` regex: `^[a-z0-9-]+\/[a-z0-9-]+$`
- `version` must be semver
- `type` must be valid
- `description` 10-200 chars
- `files.include` must match at least 1 file
- `mcp.command` required for `mcp` type

## 6. Examples

### Skill
```toml
[package]
name = "taste/skill"
version = "1.0.0"
type = "skill"
description = "Give your AI good taste — stop boring outputs"
```

### MCP
```toml
[package]
name = "mcp/github"
version = "1.5.0"
type = "mcp"
description = "GitHub MCP server — issues, PRs, repos"
[mcp]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { "GITHUB_TOKEN" = "${GITHUB_TOKEN}" }
```

### Agent
```toml
[package]
name = "agency/frontend-wizard"
version = "2.1.0"
type = "agent"
description = "Frontend wizard subagent — React, Tailwind, shadcn"
[agent]
model = "claude-sonnet-4"
tools = ["Read", "Write", "Bash", "WebFetch"]
```
